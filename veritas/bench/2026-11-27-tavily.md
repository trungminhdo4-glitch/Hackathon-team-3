Applied the native REST integration path. A CLI is not used as application runtime. No packages or global skills were installed, no agent defaults changed, and no key files were accessed.

No Tavily or OpenAI key or Tavily setup token was present in this process; values were never printed. `tvly` was not on PATH and plugin discovery found no Tavily connector. The package gate could not verify the CLI registry in its restricted invocation and returned ASK; no installation or package approval was attempted.

The documented keyless Search route was tested once against Tavily's own API documentation, then once through the implemented application's adapter. **Both requests returned HTTP 429**. The application smoke records one search, zero extracts and zero model calls, with `provider_rate_limited`. No vendor research, official blind input, successful content extraction or accuracy improvement is claimed. Unknown billing is recorded as null.

## IMPLEMENTED

The existing Tavily REST provider now accepts an explicit keyless mode. Keyed mode remains the default constructor behavior and requires a key. Keyless requests send only `X-Tavily-Access-Mode: keyless`, even if a process key exists. Search and single-URL Extract share timeout/abort and sanitized HTTP-error handling. HTTP 429 is typed, no response body or credential is logged, and there is no automatic retry.

Extract accepts a public URL and requires the returned normalized URL to match the requested one. Snippets cannot replace missing `raw_content`; failed extraction is not a negative vendor finding. Returned final redirect destination is explicitly unknown. Full extraction is requested without query/chunk joining, because joined chunks must not masquerade as one contiguous quotation.

`focused-research.js` implements a small one-question research path: **at most one search and one extraction per product**, reuse returned raw content when already available, keep snippets as discovery leads, and store bounded actual source text, timestamps and locally computed document hashes in the existing research-cache schema. It returns no vendor verdict. The result is for factual extraction and a separate judge, not a replacement submission. The first quota failure prevents later cohort searches rather than repeatedly retrying. Abort/budget failures remain unassessed records. No broader crawler or orchestration framework was added.

`resolveConfig` recognizes opt-in `--provider tavily-keyless`; existing automatic selection without a key still chooses `none`. Competition defaults are unchanged.

## TESTED

**133/133 full regression tests passed**: 109 VERITAS and 24 application tests. Nine new tests cover keyless/keyed headers, credential isolation, typed quota errors, exact source binding, unsafe URLs, missing raw content, cancellation, bounded search/extract counts, raw-content reuse and explicit configuration. Success paths are mocked tests, **not successful live Tavily verification**.

Reproduction from project root, with a fresh output directory:

```powershell
node veritas/focused-research.js --input questions.json --out tavily-question-run --provider tavily-keyless
# Once authenticated credentials are available in the runtime, use --provider tavily.
node veritas/bench/phase6-packets.mjs inputs.json tavily-question-run/cache.json judge-packets.json
```

Input is an array of `{id,url,question}`. Only those fields are consumed. The first command exits 2 if any question lacks captured evidence; it writes `cache.json` and `run.json` rather than pretending all questions were answered. A failed cache must not be sent to the judge as established evidence. The normalization command requires a complete usable cache and the matching `id,url` manifest; it does not invoke a model.

## BLOCKED

Live Tavily quality comparison is blocked by HTTP 429 and the absence of authenticated runtime credentials. Global CLI onboarding was not completed; Tavily must not be described as fully ready. Following Tavily's documented login route would require CLI package verification/owner approval where the gate asks, then normal foreground browser login and consent, followed by authentication and successful live-request verification. Never ask for a pasted secret or bypass the package gate. The requested CLI skill installation would separately require the workspace's owner/SkillSpector process; it is not needed for the existing REST runtime.

The strongest measured researcher and working fallback from Phase 6 remain unchanged. The next valid experiment is a preregistered comparison on development-only unanswered scope/support questions, at identical source-request ceilings, once Tavily actually returns usable content. Keep extraction accuracy, overall-label accuracy, costs and complete cohort failures separate. No performance improvement can be inferred from adding a provider or passing tests.
